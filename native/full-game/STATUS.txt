Script ABI/browser renderer update
----------------------------------
The original radscript library now builds with our browser virtual-call
adapter replacing the x86 assembly source (still inventoried as a platform
replacement). Runtime vcall_smoke.mjs verifies mixed integer/float/string
arguments and void/integer/float results against actual virtual C++ methods.
It also verifies the inherited AddRef/Release slots and object state.
There is no arbitrary +1 vtable offset: Wasm uses the interface's actual
method slots. Script double arguments/results fail explicitly; the supplied
retail srrtypes.typ contains no double declarations. Full script loading is
not yet runtime-tested in a game boot.

The supplied PDDI OpenGL source and browser display now compile AND LINK in
renderer_smoke.html. prepare_gl.py adapts a generated copy of the installed
Emscripten MIT-licensed GL layer, retaining its notice and recording source
hashes. No compiler installation files are changed. Exact source anchors fail
configuration on incompatible compiler versions.

Implemented graphics compatibility:
- Directional and point light shader vectors with per-light distance attenuation.
- Emissive material color and scalar-to-vector GL light/material APIs.
- WebGL-compatible RGBA texture uploads and clamp-to-edge sampler modes.
- Browser-managed texture residency (desktop hint omitted, engine priority kept).
- One-time context reset consumption, preventing per-frame texture invalidation.
- Optional desktop separate-specular extension kept outside the browser path.

The linked Node/Wasm gl_state_smoke verifies attenuation for all eight lights,
material emission and shininess in the compiled JS/Wasm layer. This does NOT
verify GPU rendering. renderer_smoke.html has real pixel checks for an original
PDDI clear and triangle. Browser execution was attempted through the existing
QtWebEngine QA runner, but the browser process failed under the sandbox with
Operation not permitted. Do not report rendererRuntimePassed=true until those
checks actually run successfully. The HTML is self-contained and needs no
network fetch to load its Wasm.

Foundation browser_fibers.cpp implements the original fiber API with real
Emscripten stack switching. fibers_smoke verifies nested switching, user data,
stack locals and resumption in Wasm. Its memory allocator is explicitly a
TEST HARNESS allocator; production fibers call original radMemory APIs.
This is not a complete thread backend and is not integrated into the original
radcore archive yet. Inspection found no gameplay/Pure3D callers of these fiber
APIs; game file loading instead uses semaphores and worker threads, which
remain unported. Fiber tests do not establish working game loading.

build-game.py reports script, fiber and GL-state runtime results independently
of renderer linking and browser drawing. Latest full build remains incomplete
with readyToPlay=false. The game does not yet boot.
